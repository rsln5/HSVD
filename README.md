# Гиперболическое сингулярное разложение

Код и воспроизводимые эксперименты к работе «Гиперболическое сингулярное
разложение (HSVD) и приложения». Репозиторий: [rsln5/HSVD](https://github.com/rsln5/HSVD).

Общий алгоритм вычисляет `A = U @ Sigma @ V.conj().T` для прямоугольных
вещественных и комплексных матриц, включая неполный ранг и нейтральные блоки.
Здесь `U.conj().T @ U = I`, `V.conj().T @ J @ V = J`,
`J = diag(I_p, -I_(n-p))`. Для сравнения реализован односторонний
гиперболический метод Якоби для матриц полного столбцового ранга.

## Установка и первый запуск

Нужен Python 3.10 или новее. Команды выполняются из корня проекта.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e '.[test,experiments]'
python -m pytest -q
```

В Windows окружение активируется командой `.venv\Scripts\activate`.
Для самого алгоритма достаточно NumPy. Дополнительные зависимости нужны
для тестов, независимых вычислений с повышенной точностью и рисунков.
Версии окружения сохранённых экспериментов указаны в
`results/contest/requirements-tested.txt`. Их можно установить отдельно:

```bash
python -m pip install -r results/contest/requirements-tested.txt
python -m pip install -e .
```

Пример с двумя нейтральными блоками:

```python
import numpy as np
from hsvd import hsvd

A = np.array([[2., 0., 2., 0.],
              [0., 1., 0., 1.]])
result = hsvd(A, p=2)
assert result.structure.j == 2
np.testing.assert_allclose(result.reconstruct(), A, atol=1e-12)
print(result.structure)
print(result.diagnostics)
```

`p` задаёт число положительных знаков в начале диагонали `J`.
Размеры факторов: `U: (m,m)`, `Sigma: (m,n)`, `V: (n,n)`.
Исходная матрица не изменяется. Используется арифметика `float64`
или `complex128`. Знаки и фазы векторов не единственны, поэтому
проверяются тождества разложения и подпространства.

## Пороги и ограничения

Параметры `rank_rtol` и `spectral_rtol` определяют численные ранги.
По умолчанию оба равны `100 * max(m,n) * np.finfo(float).eps`.
Сохраняются сингулярные числа `s_i > rank_rtol * s_max`.
Собственные значения вспомогательной матрицы считаются нулевыми при
`abs(lambda) <= spectral_rtol * s_max**2`.

`result.structure` содержит `rank`, `l_plus`, `l_minus`, `j`, `p0`, `q0`.
`result.diagnostics` содержит невязки восстановления, унитарности и
J-унитарности, дополнительную проверку преобразования, норму `V`
и ошибку усечения ранга. Допуск проверки по умолчанию — `check_tol=1e-9`.
Неверные аргументы вызывают `ValueError`. Несогласованная структура или
недостаточная точность вызывают `NumericalBreakdownError` с указанием этапа.

Малые невязки не гарантируют точный ранг или малую относительную ошибку
малых гиперболических сингулярных чисел. Отказы на трудных входах
сохраняются в протоколе вместе с причинами.

## Воспроизведение экспериментов

Проверить сохранённый протокол и соответствие таблиц без повторного замера времени:

```bash
python -m checks.render_contest_tables --export results/contest/tables.tex --check
python -m examples.cpca_real_data --check
```

Первая команда проверяет контрольные суммы исходников и входных матриц.
Вторая повторяет расчёт cPCA, проверяет сохранённые факторы и подпространства.
Обе команды работают без сети и не перезаписывают результаты.

Повторить эксперименты и построить таблицы:

```bash
python -m checks.contest_experiments
python -m checks.render_contest_tables --export results/contest/tables.tex
```

Протокол включает 107 структурных случаев, сравнение на 72 матрицах
полного столбцового ранга, пять опытов с разбросом чисел от 1 до 10⁸
и исследование порогов. Общий алгоритм запускается на всех входах.
Для Якоби явно отмечается неприменимость вне полного столбцового ранга.
Эталон малых чисел вычисляется с 80 десятичными знаками для сохранённых
входных матриц. При разбросе 10⁸ общий алгоритм с исходными порогами
останавливается на определении структуры, Якоби завершает вычисления.

Время включает построение полных факторов и проверку невязок.
Общий алгоритм использует библиотечные SVD и диагонализацию, прототип
Якоби перебирает пары столбцов в Python. Сравнение относится к этим
реализациям. При повторном запуске времена изменятся и таблицу в работе
при необходимости следует обновить вручную.

Дополнительные математические проверки:

```bash
python -m checks.verify_paper_identities
python -m checks.verify_full_construction
python -m checks.verify_error_bounds --output results/verification/error_bounds.json
```

## cPCA на открытых данных

Сравниваются проекции PCA и cPCA для 77 белковых признаков из UCI Mice
Protein Expression. Используются 270 целевых наблюдений и 135 фоновых,
параметр α=2 взят из авторского примера Abid et al. HSVD вычисляет
контрастное подпространство, которое проверяется прямой диагонализацией
разности ковариаций. Состав выборок, обработка и ограничения интерпретации
описаны в [PROVENANCE.md](results/applications/cpca_real/PROVENANCE.md).
Исходные данные распространяются по CC BY 4.0, ссылка на лицензию и
атрибуция сохранены вместе с данными.

```bash
python -m examples.cpca_real_data
python -m examples.cpca_real_data --check
```

Первая команда пересоздаёт PDF/PNG, координаты CSV, массивы NPZ и протокол.
Для обновления рисунка в работе скопируйте
`results/applications/cpca_real/pca_vs_cpca.pdf` в `paper/figures/`.
Рукопись использует готовое изображение.

## Обновление репозитория

Эта папка содержит полный актуальный комплект. При обновлении существующего
клона замените старый набор файлов этим комплектом, сохранив каталог `.git`.
Простое копирование поверх старых файлов оставит удалённые примеры и черновики.
Перед публикацией проверьте изменения через `git diff` и запустите тесты.

`SHA256SUMS.txt` фиксирует содержимое подготовленного комплекта.
Проверка выполняется из папки `github/HSVD/` или из корня распакованного ZIP:

```bash
shasum -a 256 -c SHA256SUMS.txt
```

После собственных изменений контрольные суммы нужно обновить. Для сборки
новой чистой папки и ZIP из актуальных исходников:

```bash
python -m checks.build_release --replace
```

Результат появится в `github/HSVD/` и `github/HSVD.zip`.
Ключ `--replace` обновляет предыдущую выгрузку. Изменения вносите в рабочие
файлы в корне проекта, затем пересобирайте папку `github/` этой командой.
